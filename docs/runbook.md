# Queue runbook

Inspect `/deliveries` and `/deliveries/{id}` with an authorized token. States are pending, running, delivered, dead. Use authenticated `/metrics` to distinguish a growing pending queue from repeated dead letters. Payloads and receiver response bodies are not exposed through listing endpoints.

- Worker stopped: restart only the worker. Existing running attempts become reclaimable after 30 seconds. A crash consumes one of five attempts.
- Receiver 5xx/408/429: inspect receiver health and network reachability; exponential retries proceed automatically. Do not change the idempotency key to force duplicate work.
- Receiver permanent failure: fix the contract/credential issue; the current release has no replay endpoint. A future replay operation must retain audit history and explicitly define idempotency.
- SQLite busy: check write contention and storage latency. The ten-second connection timeout is not a horizontal scaling strategy.
- Shutdown: `docker compose down` preserves the named data volume. Do not remove volumes containing wanted delivery history.

Secrets are generated by bootstrap and ignored by Git. The demo receiver deliberately fails its first two attempts for each ID. Its deduplication memory resets on restart, so do not use it for real side effects. Production backup and restore require consistent SQLite snapshots and a tested receiver deduplication policy; those are outside this release.
